<objective>
Make the web config editor tell the user that a file is read-only instead of surfacing
`[Errno 30] Read-only file system: '/etc/pellmon/pellmon.conf'`.

Purpose: `config/pellmon.conf` stays mounted read-only on purpose (it holds password hashes), so
attempting to save it is an expected, explainable outcome rather than an error to debug (D-08).
Output: an errno-aware branch in `Pellmonconf.save`, a safer render of the message in the editor's
JS, and unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `Pellmonconf.save` | Untrusted filename/data crosses into a file write |
| server error text → browser DOM | Error strings are rendered into `#filename_header` |
| container → `/etc/pellmon` | Only `conf.d` is writable; `pellmon.conf` is `:ro` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-13 | Tampering | arbitrary file write via `filename` | mitigate | `_resolve` allowlist + realpath containment left untouched; regression tests in `test_pellmonconf_path_traversal.py` must stay green |
| T-07-14 | Spoofing / CSRF | cross-origin save | mitigate | `_check_same_origin()` branch untouched; `test_pellmonconf_csrf.py` must stay green |
| T-07-15 | Information Disclosure | raw OSError exposing absolute container paths to the browser | mitigate | Permission-class errors are replaced with a message that names only the allowlisted filename |
| T-07-16 | Tampering (XSS) | error string inserted with jQuery `.html()` | mitigate | Switch to `.text()` in `source.js` |
| T-07-17 | Tampering | web user rewriting `pellmon.conf` password hashes | mitigate | Enforced by the `:ro` mount from plan 07-01; this plan only changes the message shown |
| T-07-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan |
</threat_model>
