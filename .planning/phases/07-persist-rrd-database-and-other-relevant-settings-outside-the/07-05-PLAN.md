<interfaces>
Facts to document (all decided in this phase):
- Data folder: `${PELLMON_DATA_DIR:-./pellmon-data}` with `data/` (rrd.db, pellmon_settings.db) and
  `logs/`; set `PELLMON_DATA_DIR` in `.env` to an absolute path or a `./`-prefixed path (a bare name
  becomes a Docker named volume).
- `pellmon-init` runs as root before `pellmonsrv`, creates the folders and chowns them plus
  `config/conf.d` to 999:999; consequence: editing `config/conf.d/*.conf` on the host afterwards
  needs `sudo`, while the web config editor can save them.
- `config/pellmon.conf` stays read-only in both containers; the editor now answers
  "<file> is read-only ..." instead of an errno message. The editor itself is the standalone
  `pellmonconf` tool (port 8083); the compose stack does not start it today, so D-08 is satisfied
  (writable `conf.d` + friendly message) but is not exercised by `docker compose up` — say this
  plainly in the guide rather than implying a working in-stack editor.
- Backup (run from the repo root, the folder containing `docker-compose.yml` and `config/`):
  `python3 tools/pellmon_backup.py backup --out pellmon-backup-<date>.tar.gz`
  (archive is 0600 and contains password hashes and the settings DB — keep it private);
  restore: `python3 tools/pellmon_backup.py restore pellmon-backup-<date>.tar.gz --yes` (stops the
  daemon, rebuilds the RRD with `rrdtool restore`, restarts). Works PC → Pi because the RRD travels
  as XML.
  **Why the working directory matters:** the RRD path comes from `config/conf.d/database.conf`
  (`/var/lib/pellmon/rrd.db`), which overrides `config/pellmon.conf`. `[conf] config_dir` in that
  file is the *container* path `/etc/pellmon/conf.d`, so the tool reads the host copy next to
  `pellmon.conf` (`./config/conf.d`) instead. Running from another directory needs
  `--config /path/to/config/pellmon.conf`; if your `conf.d` is somewhere else entirely, pass
  `--host-config-dir /path/to/conf.d`. Add `--verbose` to see which directory and RRD path were
  resolved. If no `database` value can be found the tool exits 1 with a message naming the config
  file — it never guesses.
- One-time migration off the old named volume (D-11, manual, best effort):
  `docker run --rm -v <project>_pellmon-data:/from -v "$PWD/pellmon-data/data":/to pellmon:latest sh -c 'cp -a /from/. /to/'`
  then `docker compose up -d` (init fixes ownership). Find the exact volume name with
  `docker volume ls`. A raw copy is only valid on the same machine type; otherwise use the backup
  tool instead.
- `DEPLOY-PI.md` currently documents backups as "the RRD database lives in the `pellmon-data`
  volume" (section 6) and reads logs via `docker run --rm -v pellmon_pellmon-logs:...` — both are
  now wrong and must be rewritten to the bind-mount paths.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| documentation → operator actions | Wrong instructions can make an operator world-open the data folder or lose it |
| backup archive → operator storage | Archives carry password hashes and the settings DB |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-24 | Information Disclosure | operator emailing/copying a backup archive to shared storage | mitigate | The guide states the archive is 0600 and contains password hashes and the MQTT secret, and must be kept private |
| T-07-25 | Elevation of Privilege | operator "fixing" permissions with `chmod -R 777` on the data or conf.d folder | mitigate | The guide gives the exact supported fix (`docker compose run --rm pellmon-init`, or `sudo chown -R 999:999 <PELLMON_DATA_DIR>`) and explains why `sudo` is needed for host edits |
| T-07-26 | Repudiation / data loss | operator running the raw volume copy across machine types | mitigate | Migration step says a raw copy is valid only on the same machine type and points to the backup tool otherwise |
| T-07-27 | Spoofing | no GUI backup endpoint added by mistake | mitigate | D-12 documented as deferred; no web route is added in this phase (verified by the absence of changes to `src/Pellmonweb/pellmonweb.py`) |
| T-07-29 | Repudiation / data loss | operator running the backup from the wrong directory and archiving a nonexistent RRD | mitigate | The guide requires running from the repo root and explains `--config`/`--host-config-dir`; smoke step 7a records the resolved path and 7f records the no-guess error |
| T-07-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan |
</threat_model>
