    Create `tools/version_bump.py` implementing the `<interfaces>` contract above. Per D-05 this is
    Python only — no PowerShell, no Bash, no new pip dependencies (stdlib `argparse`, `logging`, `os`,
    `re`, `subprocess`, `sys` only).

    Conventions, all mandatory: the verbatim GPL header block copied from `tools/pellmon_backup.py`
    lines 1-18, followed by a tool docstring documenting the `decide` subcommand and its
    `--dry-run`/`--type`/`--version-file` flags; `logger = logging.getLogger('version_bump')` (a
    standalone-script logger, NOT the shared `'pellMon'` daemon logger); `%`-style formatting in all
    log and error messages, never f-strings; no type hints.

    Algorithm (ported 1:1 from the reference doc via D-03 — do not invent new patterns, do not add
    `docs:`/`chore:`/`perf:` handling): module-level `_FEAT_RE = re.compile(r'^feat(\(.+\))?:')` and
    `_FIX_RE = re.compile(r'^fix(\(.+\))?:')`. `decide_bump(commit_messages)` checks, in this order,
    (1) `'BREAKING CHANGE' in line` for any line — bare substring, case-sensitive, not anchored — ->
    `'major'`, (2) `_FEAT_RE.match(line)` for any line -> `'minor'`, (3) `_FIX_RE.match(line)` for any
    line -> `'patch'`, (4) `None`. It performs zero I/O (D-06).

    `parse_version(text)`: `.strip()`, split on `'.'`, require exactly 3 parts each `int()`-parseable,
    otherwise `raise ValueError` naming the offending content (Pitfall 3 — never silently coerce, never
    strip a `v` prefix). `format_version` joins with `'.'`. `read_version(path)` reads the file and
    delegates to `parse_version`; `write_version(path, version_tuple)` writes
    `format_version(...) + '\n'` (trailing newline, no `v` prefix).

    `_run(argv, check=True, capture=False)` mirrors `pellmon_backup.py:74-83` — list argv, never
    `shell=True`. `last_tag()` runs `['git', 'describe', '--tags', '--abbrev=0']` with `check=False`
    and returns `None` on a non-zero return code (Pitfall 4 — this repo has zero tags today, so the
    first real run takes this branch). `commits_since(tag)` runs
    `['git', 'log', '%s..HEAD' % tag, '--pretty=%B']` when a tag exists, else
    `['git', 'log', '--pretty=%B']`, and returns `result.stdout.splitlines()` — the splitlines() call
    lives here, in the caller, exactly as Task 1's test asserts.

    CLI: `parse_args` uses `add_subparsers(dest='command', required=True)` with one `decide`
    subparser carrying `--dry-run` (compute and print, write nothing), `--type` with
    `choices=['major','minor','patch']` (force a bump, skip commit analysis), and `--version-file`
    defaulting to `'VERSION'`. Dispatch: resolve the bump (from `--type` if given, else
    `decide_bump(commits_since(last_tag()))`); if it is `None`, log `'no release needed'` to stderr,
    emit `bump=none` and no `version=` line, and return 0 without touching the VERSION file; otherwise
    compute the new tuple with `apply_bump`, write it unless `--dry-run`, and emit
    `bump=<type>` and `version=<x.y.z>`. Emission goes to stdout AND, when `os.environ.get('GITHUB_OUTPUT')`
    is set, is appended to that file — this is how Plan 02's workflow reads the result.

    `main(argv=None)` copies `pellmon_backup.py`'s top-level idiom: wrap the dispatch in
    `try/except (ValueError, OSError, subprocess.CalledProcessError) as e`, write
    `'error: %s\n' % e` to `sys.stderr`, return 1; end the file with
    `if __name__ == '__main__': sys.exit(main())`.

    Per D-08, do not read, write, or reference `configure.ac` or `src/Pellmonsrv/version.py.in` from
    this script — `VERSION` is the sole source of truth for the Docker image tag only.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git history -> version_bump.py | Commit message text (attacker-influenceable via a PR title/body that lands on master) is read as input |
| VERSION file -> version_bump.py | On-disk text parsed into an integer triple that later becomes a published image tag |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | `_run()` git shell-outs in `tools/version_bump.py` | mitigate | All external commands go through `_run()` with a list argv and never `shell=True`, so commit message content can never be interpreted as shell syntax (asserted: `grep -c "shell=True"` returns 0) |
| T-09-02 | Tampering | `VERSION` parsing | mitigate | `parse_version` hard-fails with `ValueError` on anything that is not exactly three int-parseable dot-separated parts after strip; no coercion, no `v`-prefix stripping, so a malformed VERSION cannot silently produce an unexpected published tag (Pitfall 3) |
| T-09-03 | Denial of Service | Bump decision on an untagged repo | mitigate | `last_tag()` uses `check=False` and treats a non-zero exit as "no tag", so the genuine first run (zero tags in this repo today) computes from full history instead of crashing the release pipeline (Pitfall 4) |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | No packages are installed by this phase — `tools/version_bump.py` is stdlib-only (argparse, logging, os, re, subprocess, sys), confirmed in 09-RESEARCH.md's Package Legitimacy Audit as N/A |
</threat_model>
