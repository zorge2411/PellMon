# Phase 10 - UI Design Contract

> Visual and interaction contract for making the existing Bootstrap 3 PellMon UI usable at 390px (phone) and correct at 768px (tablet). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Auto mode: no questions asked; CONTEXT.md decisions D-01..D-06 are locked. Items marked (defaulted) were chosen by the researcher where CONTEXT.md left discretion.

This is a responsive-layout phase. No new pages, features, fonts, colors, frameworks or build steps. Desktop (>= 992px) rendering must be unchanged.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (server-rendered Mako + vendored Bootstrap 3 at `media/bs3`; shadcn gate not applicable) |
| Preset | not applicable |
| Component library | Bootstrap 3 (grid, `collapse`, `btn`, `panel`, `nav`, responsive utilities), jQuery 1.11, flot |
| Icon library | Bootstrap 3 Glyphicons (already bundled); only `glyphicon-chevron-down` / `glyphicon-chevron-up` added, for collapse toggles |
| Font | Bootstrap 3 default stack; no custom font |

Where CSS lives (defaulted): all new rules go in the existing `src/Pellmonweb/media/css/pellmon.css`, appended in one block headed `/* Phase 10: mobile / responsive */`. No new stylesheet, no new `<link>`. The page-local `<style>` block in `parameters.html` may receive small additions only where it already owns the selector.

## Breakpoints and Design Widths

Bootstrap 3 breakpoints are used as-is; no custom values.

| Name | Range | Bootstrap tier | Role |
|------|-------|----------------|------|
| Phone | < 768px | `xs` | Primary target, designed at 390px viewport (container content width 360px) |
| Tablet | 768px - 991px | `sm` | Verified at 768px viewport (container 750px) |
| Desktop | >= 992px | `md`/`lg` | Unchanged from today |

Media queries used in `pellmon.css` (exactly these three, no others):
- `@media (max-width: 767px)` phone rules
- `@media (min-width: 768px) and (max-width: 991px)` tablet-only rules
- `@media (min-width: 768px)` (already exists for `.dl-horizontal`; keep untouched)

Dashboard on tablet (defaulted): stays single column at 768px (widgets use `col-xs-12 col-md-N`, so they only go side by side from 992px, exactly as today). Tablet gets the taller graph/chart (below) and a fully expanded events list.

## Spacing Scale

Declared values (multiples of 4), used by all new rules:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between chevron glyph and label |
| sm | 8px | Gap between wrapped control links / buttons, events preview padding |
| md | 16px | Vertical gap between stacked widgets and stacked form controls |
| lg | 24px | Gap between collapsible Parameters sections |
| xl | 32px | Not used |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Exceptions: (1) Bootstrap 3 native 15px column gutters and container padding are kept as-is. (2) Touch target minimum is 44px (see Tap Targets); it is a size, not spacing, and overrides the scale for heights. (3) Graph and chart heights (260 / 320 / 400px), the 230px `#systemimage` min-height, the 96px events preview and the 96px gallery thumbnail cap are layout dimensions, not spacing. (4) The 3px transparent `border-top` on `a.lineselection:not(.selected)` mirrors Bootstrap's existing 3px selected border so links do not jump; it is a border width, not a spacing token. Every padding and margin value newly declared by this phase is on the 4/8/16/24 scale.

Page must never overflow horizontally: container padding stays 15px at 390px, giving 360px of content width.

## Typography

Bootstrap 3 base retained; no size or weight is changed on desktop. New rules use only these four sizes (14, 16, 18, 24). Any pre-existing 12px text elsewhere in the desktop UI is unchanged and is not a declared role of this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / control text (also helper text, gallery captions, toggle sub-text) | 14px | 400 | 1.43 (Bootstrap default, accepted) |
| Input (phone `.form-control` only) | 16px | 400 | 1.43 |
| Heading (widget `h4`, Parameters section heading/toggle) | 18px | 600 on phones (Bootstrap default 500 on tablet/desktop, unchanged) | 1.2 on phones (Bootstrap default 1.1 on tablet/desktop, unchanged) |
| Display (page `h1`) | 24px on phones (Bootstrap is 36px), unchanged from 768px up | 600 | 1.2 |

Weights: exactly 400 and 600 for every value declared or set by this phase. Every new rule sets weight explicitly (400 or 600) and, for headings, line-height 1.2. Pre-existing Bootstrap values that this phase does not touch (desktop/tablet headings at weight 500 and line-height 1.1, Bootstrap `h3` at 24px on desktop/tablet) are inherited and unchanged, and are not roles of this phase.

Explicit phone rules (all inside `@media (max-width: 767px)`, desktop and tablet unchanged):
`h1, #pellmon-widgets h4 { font-weight: 600; line-height: 1.2; }`
`.param-section-heading { margin: 0 0 8px; font-size: 18px; font-weight: 600; line-height: 1.2; }`
`.param-section-toggle { font-size: 18px; font-weight: 600; line-height: 1.2; }` (a `.btn` would otherwise render 14px/400, and `font:inherit` is applied only from 768px, where the toggle inherits the h3 look of today).
Result: on phones the Parameters section toggle renders at 18px/600, matching the table. Phone rule: `h1 { font-size: 24px; }` inside the `max-width: 767px` query only. Text inputs on phones use `font-size: 16px` (prevents iOS focus-zoom); this is the one place 16px is used, applied via `.form-control` at `max-width: 767px`. Helper text, gallery captions and toggle sub-text use the 14px body size.

## Layout Contract by Widget

### Shared shell (`layout.html`)
- Keep `<meta name="viewport" content="width=device-width, initial-scale=1.0">` exactly (structural test asserts it). Do not add `maximum-scale` or `user-scalable=no` (defaulted: keep pinch-zoom available for accessibility).
- Navbar keeps `navbar-toggle` / `navbar-collapse collapse`. Only the tap-target CSS above is added. The hamburger already exists but has no accessible name today (icon-bars only): add `aria-label="Toggle navigation"` and `aria-expanded="false"` to the `<button class="navbar-toggle">` in `layout.html` (Bootstrap 3 updates `aria-expanded` on toggle), plus `<span class="sr-only">Toggle navigation</span>` as the first child.
- `body { overflow-x: hidden; }` is NOT allowed as a fix; overflow must be fixed at source (see Acceptance).
- Add to `pellmon.css` (all viewports): `img, object, svg { max-width: 100%; }`, `.container { overflow-wrap: break-word; }`.

### Dashboard rows (`index.html`)
- Change the column class to `col-xs-12 col-md-${width}` (was `col-md-${width}`). DOM order is preserved, so phones render: System image, Events, Graph, Consumption, Silo level (matches D-03 with default `frontpage_widgets`).
- Each widget column gets bottom spacing on phones: `#pellmon-widgets [class*="col-"] { margin-bottom: 16px; }` inside `max-width: 767px`.

### System image (`systemimage`)
- The system image is the visual anchor and first focal point of the phone dashboard: it is the first widget, the largest visual element above the fold, and nothing above it except the navbar and `h1`.
- Keep `<object id="systemimage" class="image-responsive">`. Every diagram SVG is `width="100%" height="100%"` with a viewBox (330x280, 440x280, 440x310), and an `<object>` with `width:100%` and no height renders at the 150px default, which makes the diagram tiny. Contract (`max-width: 991px`): `object#systemimage { width: 100%; height: auto; aspect-ratio: 11 / 7; min-height: 230px; }` (11/7 = 440x280). Desktop (>= 992px) untouched.
- Acceptance: at 390px the object is 360px wide, height >= 230px, right edge <= viewport width.

### Events (`events`, D-03)
Markup (defaulted; `#lines` MUST keep its id and `data-url`, because `logview.js` `getLog()` replaces `#lines` innerHTML via `container.html(data)`; the toggle therefore lives outside `#lines`):

```
<h4>Events</h4>
<div id="events-wrap" class="events-collapsed">
  <div id="lines" data-url="${webroot}/logview/getlines?linenum=7"></div>
</div>
<button type="button" class="btn btn-default btn-block events-toggle visible-xs-block"
        aria-expanded="false" aria-controls="lines">Show all events</button>
```

- Implementation: a plain class toggle (not Bootstrap `collapse`, which cannot show a partial preview). A ~10-line inline script at the bottom of the `events` template (or in `index.js`) toggles `events-collapsed` on `#events-wrap`, flips `aria-expanded`, and swaps the button text. It must not touch `#lines` children, so websocket/ajax updates keep working while collapsed or expanded.
- CSS: `@media (max-width: 767px) { #events-wrap.events-collapsed { max-height: 96px; overflow: hidden; } }`. At >= 768px the wrap has no max-height and the button is hidden by `visible-xs-block`, so tablet and desktop always show the full list.
- Initial state on phones: collapsed (button reads "Show all events", `aria-expanded="false"`). State is not persisted (defaulted).
- Log line graph images opened inside a line: `.loglink img { max-width: 100%; height: auto; }`.
- `#lines { overflow-wrap: anywhere; }`.

### Graph (`graph`, D-04)
- Remove the inline `style="height:400px"`; use `<div id="graph" class="pellmon-graph"></div>`. Heights via CSS: `.pellmon-graph { height: 260px; }` (< 768px); `@media (min-width: 768px) and (max-width: 991px) { .pellmon-graph { height: 320px; } }` (defaulted); `@media (min-width: 992px) { .pellmon-graph { height: 400px; } }` (unchanged from today). flot.resize already reflows on width change; no JS change to the plot options.
- Controls markup (defaulted; keeps every existing class and `data-*` attribute that `index.js` binds: `.lineselection`, `.timeChoice`, `.autorefresh`, `.selected`, `data-linename`, `data-selected`, `data-time-choice`, `data-title-text`, and the `Back`/`Forward` `.btn.left` / `.btn.right`):
  - Line-selection links wrapped in `<div class="graph-lines">`, time links + Autorefresh in `<div class="graph-times">`, Back/Forward in `<div class="btn-grp graph-nav">`. Fix the existing typo `</div   >`.
  - The `&nbsp;&nbsp;` separators are removed on phones' behalf by spacing rules; keep them in markup if easier (they collapse harmlessly), but link spacing on phones comes from `margin: 0 8px 8px 0`.
  - `@media (max-width: 767px)`: `.graph-lines a, .graph-times a { display:inline-block; min-height:44px; line-height:40px; padding:0 16px; margin:0 8px 8px 0; }`; `.graph-times.pull-left, .graph-nav.pull-right { float:none !important; }`; `.graph-nav { display:flex; gap:8px; }` `.graph-nav .btn { flex:1 1 50%; min-height:44px; padding:8px 16px; line-height:28px; }`.
  - Unselected line links must not jump when selected (selected adds a 3px top border): `@media (max-width:767px) { a.lineselection:not(.selected) { border-top: 3px solid transparent !important; } }` (inline `border-top-color` from the template loses to `!important`, and `border-top: 3px solid` is set by `.selected`).
  - Controls wrap onto multiple lines; nothing may extend past 360px.
- Header `h4.graphtitle` unchanged. No flot navigate/pan/zoom changes; no touch handlers added (deferred).
- Tooltip: `#tooltip { max-width: 200px; }` so it cannot push the page wider than the viewport.

### Consumption and Silo level plugin widgets
The plugin templates hard-code `style="height:400px"` (`src/Pellmonsrv/plugins/consumption/__init__.py` line ~87, `src/Pellmonsrv/plugins/silolevel/__init__.py` line ~109). Contract: replace the inline height with `class="image-responsive pellmon-chart"` and share the graph height rules: `.pellmon-chart` = 260px (< 768), 320px (768-991), 400px (>= 992). Same CSS block as `.pellmon-graph` (use a combined selector). Server-side change is limited to this string edit (`%`-style formatting, untyped, per project convention).
`consumption.html` (Consumption page): columns become `col-xs-12 col-md-6` (was `col-md-6`), so the four charts stack on phones and tablets.

### Parameters page (`parameters.html`, D-05)
Structure on phones, top to bottom: `h1`, tag navigation, "Less../More.." link, Control section, Data section, Settings section.
- Grid: sidebar `col-xs-12 col-md-2`; content `col-xs-12 col-md-10`; Data and Settings columns `col-xs-12 col-md-5`; Control `col-xs-12`.
- Tag navigation on phones: two pills per row. `.param-tags` class added to the `nav nav-pills nav-stacked` list; `@media (max-width:767px) { .param-tags > li, .param-tags > li + li { float:left; width:calc(50% - 8px); margin:0 4px 8px; } .param-tags > li > a { min-height:44px; padding:8px; line-height:28px; } }`. From 768px up it stays stacked as today.
- Collapsible sections (Bootstrap 3 `collapse`): each of Control, Data, Settings gets a header toggle and a body:
  ```
  <h3 class="param-section-heading">
    <a class="param-section-toggle btn btn-default btn-block" data-toggle="collapse" href="#param-data" aria-expanded="true" aria-controls="param-data">Data <span class="glyphicon glyphicon-chevron-up"></span></a>
  </h3>
  <div id="param-data" class="collapse in param-section"> ...dl... </div>
  ```
  Default state on phones (defaulted): Control open (`collapse in`), Data open (`collapse in`), Settings collapsed (`collapse`, `aria-expanded="false"`). Chevron flips via the `collapsed` class that Bootstrap toggles on the trigger; pure CSS, no extra JS (`.param-section-toggle.collapsed .glyphicon-chevron-up` swapped by `content` or by two glyph spans shown/hidden with `.collapsed`).
  Desktop and tablet stay unchanged with no JS: `@media (min-width: 768px) { .param-section.collapse { display: block !important; } .param-section-toggle { pointer-events:none; } .param-section-toggle .glyphicon { display:none; } }`, and the toggle is styled as a plain heading there (`background:none; border:0; padding:0; text-align:left; font:inherit; box-shadow:none`) so it looks like today's `h3`. Section labels are the same as today: "Control", "Data", "Settings".
  Values keep updating while a section is collapsed (spans stay in the DOM; only `display` changes).
- Rows: on phones each label (`dt`) sits above its value (`dd`), which is already Bootstrap's `dl-horizontal` behavior below 768px; add `dt { margin-top: 16px; }` and `dd { margin-left: 0; }` at `max-width: 767px`. Clicking a `dt`/`dd` still reveals `.details`.
- Inputs: `.details .form-inline .form-control { width: 60%; }` becomes `width: 100%` on phones, and the `Set` button goes on its own row, full width (`.details .form-inline .btn { display:block; width:100%; margin-top:8px; }`); select boxes `width:100%`. Input and select height 44px.
- Command buttons: the `btn-group` wraps on phones: `@media (max-width:767px) { .btn-group > .command.btn { float:none; display:block; width:100%; margin:0 0 8px; border-radius:4px; } }`. Also `.details { z-index: auto; }` is not required; leave the inline `z-index:10000` untouched.

### Settings page (`settings.html`, D-05, consistent with Phase 8)
- Gallery tiles: change `col-xs-12 col-sm-6 col-md-4` to `col-xs-6 col-sm-6 col-md-4` (2 per row on phones, 2 on tablet, 3 on desktop). Rows keep the Bootstrap gutter (15px), so tiles are 165px wide at 390px.

The Phase 8 states (default, hover, focus, selected, Current label, check glyph) are unchanged.
- `Save image` button becomes full width on phones (`btn-block` behavior via CSS at `max-width: 767px`), height >= 44px; helper text uses the 14px body size.
- Panel and alert markup unchanged. If Phase 6 later adds more panels they stack naturally.

## Defaulted Decisions (summary for planner)

1. All CSS in `pellmon.css`; no new stylesheet or JS library.
2. Dashboard stays single column through 991px; taller graph at 768px (320px).
3. Events collapse is a class toggle with a 96px preview, not Bootstrap `collapse`; not persisted.
4. Parameters: Control and Data open, Settings collapsed by default on phones; sections always expanded from 768px, using pure CSS (`display:block !important` at >= 768px).
5. Pinch-zoom stays enabled (no `maximum-scale`).
