<objective>
Build the two pure, Windows-importable modules the rest of the phase sits on: the entity table with the discovery payload builder, and the settings model with validators and storage.

Purpose: Topic names, unique ids, ranges and the command-off discovery behaviour (D-01..D-05, D-07, D-18, D-19 C1/C2) are the parts most likely to silently break the existing Home Assistant device; pinning them in pure, test-first modules makes the bridge (06-05) and the web page (06-06) straightforward. The settings module is the single authoritative validator used by both the daemon and the web controller.
Output: `entities.py`, `settings.py` in `src/Pellmonsrv/plugins/homeassistant/` and their tests. No `__init__.py` is created here (06-07 owns it); Python 3 imports the directory as a namespace package until then.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser form / D-Bus JSON -> validate() | Untrusted settings values enter the daemon |
| settings -> MQTT topics | Prefixes become topic segments on a shared broker |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | Tampering | prefix/discovery_prefix | mitigate | fullmatch segment regex forbids +, #, $, spaces, leading/trailing/double slash (topic injection, wildcard publishing) |
| T-06-04 | Information disclosure | password storage | mitigate | Separate key mqtt.password, never in mqtt.config JSON, public_view has only has_password; caplog sentinel tests |
| T-06-05 | Tampering | host field | mitigate | Character whitelist, no scheme, no spaces, no brackets, length cap |
| T-06-05b | Tampering / Spoofing | tls_verify downgrade via a disabled, unsubmitted checkbox | mitigate | tls_verify only changes when TLS is on and the marker is present; otherwise the stored value (default True) is kept; tests cover TLS-off saves and TLS enabled from a TLS-off page |
| T-06-06 | Spoofing | Home Assistant device takeover | accept | Identifiers come from the user; a wrong id only creates a second device (documented in 06-09) |
</threat_model>
