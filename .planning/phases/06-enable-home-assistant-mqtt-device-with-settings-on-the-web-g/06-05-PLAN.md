<objective>
Implement the MQTT bridge: one worker thread (plus paho's network thread) that owns connection, availability, discovery, state publishing, Home Assistant commands, live reconfigure, status and the connection test. Everything is driven by an injectable client factory and injectable clocks so every behaviour is tested against the in-memory fakes from 06-01.

Purpose: This is the heart of D-04..D-09 and D-13..D-19. Keeping it a pure, single-threaded state machine behind a queue makes the concurrency risk (RESEARCH "Main risks" 1) testable.
Output: `bridge.py` and two test files.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MQTT broker -> bridge | Any client that can publish on the broker can send /set messages |
| bridge -> burner (db.set_value) | Validated values become serial writes to burner memory |
| bridge -> broker | Credentials and TLS settings are used to connect |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-15 | Elevation of privilege | /set handling | mitigate | Commands off by default, explicit per-entity subscriptions only when allowed, whitelist of 10 numbers + 2 buttons, Burner ON/OFF never accepted |
| T-06-16 | Tampering | command values | mitigate | Finite integral numbers inside the HA range intersected with the datamap item range; min/max power cross-check |
| T-06-17 | Tampering (replay) | retained /set | mitigate | Retained command messages ignored and logged |
| T-06-18 | Denial of service | command flood / EEPROM wear | mitigate | 32-byte payload cap, bounded queue of 20, 2 s dedupe, 5 s per item, 10 writes per minute |
| T-06-19 | Denial of service | paho network thread | mitigate | Callbacks only enqueue; serial I/O only on the worker |
| T-06-20 | Information disclosure | logs / status | mitigate | Password never logged or in status; reasons are a fixed mapped set; sentinel caplog test |
| T-06-21 | Spoofing | broker identity | mitigate | TLS CERT_REQUIRED by default; insecure only when the user unticks Verify |
| T-06-22 | Denial of service | test-connection client | mitigate | Random client id so the live session is not kicked; one test at a time; bounded timeout |
| T-06-23 | Repudiation | commands | mitigate | One log line per accepted/rejected command with topic, item, value, result (D-09) |
</threat_model>
