# Phase 6 - UI Design Contract

> Visual and interaction contract for the "Home Assistant / MQTT" settings page and its menu entry. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Auto mode: no questions asked. CONTEXT.md decisions D-06, D-10..D-13 are locked; the Phase 8 UI-SPEC (Settings page patterns, alert style) and the approved Phase 10 UI-SPEC (mobile contract) are inherited and this page MUST conform to both. Items marked (defaulted) were chosen by the researcher where those documents left discretion.

Scope: one new server-rendered page plus one navbar item. No new fonts, colors, frameworks, icon sets, JS libraries or build steps.

## Page Layout (D-10, D-11)

`div.container.mqtt-page` > `h1` "Home Assistant / MQTT" > intro paragraph (`p.mqtt-intro`) > status line > one `<form>` containing five panels > action row (`div.mqtt-actions`). Vertical rhythm, top to bottom: h1, 16px, intro, 16px, status line, 24px, first panel, 16px between panels, 24px, action row, 32px page bottom.

Focal point: the status line is the visual anchor of the page (first colored element, above the fold, checked by H-B1); "Save settings" is the single primary action, the only accent-colored element, at the end of the form. Test connection is deliberately neutral so it never competes with Save.

One single form (deviation from Phase 8's one-form-per-section, on purpose: Save applies all fields together and reconnects once, D-13). Panels are `section.panel.panel-default` with a `.panel-heading` and `.panel-body`. Fields are stacked (label above control), not `form-horizontal`.

Intro paragraph (below h1): "Publish the burner to Home Assistant as an MQTT device. Changes are applied to the running server without a restart."

### Status line (D-13)
`<div id="mqtt-status" class="alert ..." role="status" aria-live="polite">`, placed between the intro and the form, above the fold at 390px. Server-rendered on load; if JS is available, refreshed every 5 seconds from `GET .../status` (text is replaced only when it changes, so screen readers are not spammed). Without JS the page shows the state at load time. Contents: glyph, the state word (Connected / Disconnected / Off) at weight 600, then the sentence at weight 400. Times are the server's local time in `HH:MM:SS` (`title` attribute holds the full date and time).

| State | Style | Copy |
|-------|-------|------|
| Off (enable switch off) | neutral `well` | Off. Home Assistant publishing is turned off. Turn on "Enable Home Assistant MQTT" and save to connect. |
| Connecting | neutral `well` | Connecting to {host}:{port}... |
| Connected, publishing | `alert-success` + `glyphicon-ok` | Connected to {host}:{port}. Last publish: {HH:MM:SS}. |
| Connected, nothing published yet | `alert-success` | Connected to {host}:{port}. No values published yet. |
| Connected, burner offline (D-14) | `alert-warning` | Connected to {host}:{port}, but the burner is not connected. Home Assistant shows the entities as unavailable until it answers again. |
| Disconnected | `alert-danger` + `glyphicon-remove` | Disconnected from {host}:{port}: {reason}. PellMon keeps retrying automatically. |
| Plugin not active | `alert-warning` | The Home Assistant MQTT plugin is not active on the server. Check the PellMon installation and restart the server. |
| Daemon down | `alert-warning` | Cannot read the status because the PellMon server is not running. Start the server to see the status. |

Reason strings are a fixed mapped set, never raw exception text and never containing credentials: "connection refused", "host not found", "timed out", "wrong username or password", "not authorised", "certificate could not be verified", "TLS handshake failed", "connection lost". Anything else: "unknown error (see the server log)".

### Panel 1: Connection
Heading "Connection".
1. **Enable switch** (`name="enabled"`): checkbox row, label "Enable Home Assistant MQTT". Help: "When off, PellMon does not connect to the broker or publish anything."
2. **Broker host** (`name="host"`, `type="text"`, `autocomplete="off"`, `autocapitalize="none"`, `spellcheck="false"`): label "Broker host", placeholder "mqtt.example.com or 192.168.1.10". Help: "Host name or IP address of your MQTT broker." Layout `col-xs-12 col-sm-8`.
3. **Port** (`name="port"`, `type="number"`, `inputmode="numeric"`, `min=1`, `max=65535`, default 1883): label "Port". Help: "Usually 1883, or 8883 with TLS." `col-xs-12 col-sm-4`. When the TLS checkbox is toggled and the port still equals the other standard port (1883 / 8883), JS swaps it; any other value is left alone (defaulted).
4. **Username** (`name="username"`, `autocomplete="off"`): label "Username". Help: "Leave empty if the broker allows anonymous access." `col-xs-12 col-sm-6`.
5. **Password** (`name="password"`, `type="password"`, `autocomplete="new-password"`): label "Password" `col-xs-12 col-sm-6`. Behaviour (D-12), non-negotiable:
   - The HTML never contains the stored password: no `value` attribute, not in the page, not in `status`, not in error re-renders, not in logs.
   - Password stored: placeholder is exactly `set`; help "A password is stored. Leave this field blank to keep it." Plus checkbox `name="clear_password"` labelled "Remove the stored password" (defaulted, shown only when a password is stored; blank alone never clears).
   - No password stored: placeholder empty; help "No password stored."
   - Typing a new value replaces the stored one on save; blank keeps the current one. There is no "show password" toggle.
   - If validation fails after the user typed a password, the field re-renders empty and its help reads "Re-enter the password. It is not kept when the form is redisplayed."

### Panel 2: Security (TLS)
Heading "Security".
1. **TLS** (`name="tls"`): checkbox "Use TLS (encrypted connection)". Help: "Encrypts the connection to the broker. Enter the TLS port, usually 8883."
2. **Verify certificate** (`name="tls_verify"`, default checked): checkbox "Verify the broker certificate", indented under TLS with `.mqtt-indent` (24px left margin at every width; on phones the checkbox row's own 32px label offset applies inside it). Disabled (native `disabled` plus muted text) while TLS is unchecked. Help: "Checks that the broker's certificate is valid and matches the host name. Client certificates and custom CAs are not supported yet."
3. When TLS is on and Verify is unchecked, an inline `alert alert-warning` (`role="status"`) is shown: "Certificate verification is off. The connection is encrypted, but PellMon does not check who the broker is." Shown live by JS and rendered server-side on load.

### Panel 3: Topics and discovery
Heading "Topics and discovery".
1. **Topic prefix** (`name="prefix"`, default `scotte`): label "Topic prefix", help "Values are published to <code>{prefix}/&lt;item&gt;/state</code>. Keep the default to match your existing dashboards." `col-xs-12 col-sm-6`. The `{prefix}` in the help text updates live as the user types (visual only).
2. **Discovery prefix** (`name="discovery_prefix"`, default `homeassistant`): label "Discovery prefix", help "Must match the MQTT discovery prefix configured in Home Assistant. The default is <code>homeassistant</code>." `col-xs-12 col-sm-6`.

### Panel 4: Device
Heading "Device".
1. **Device identifier** (`name="device_id"`, `autocomplete="off"`, no default, never hard-coded): label "Device identifier". Help: "Enter the identifier of your existing Home Assistant device so its entities and history carry over. A different identifier creates a new device. Switch off the old publisher first." `col-xs-12 col-sm-6`.
2. **Device name** (`name="device_name"`, no default, placeholder "Pellet burner"): label "Device name". Help: "The name shown for the device in Home Assistant." `col-xs-12 col-sm-6`.

### Panel 5: Behaviour
Heading "Behaviour".
1. **Allow commands switch** (`name="allow_commands"`, default OFF, D-06): checkbox row, label "Allow commands from Home Assistant". Help: "Lets Home Assistant change burner settings (temperature setpoints, power limits, cleaning and feeder values) and press Reset alarm and Reset ignition. Burner ON and OFF are never available from Home Assistant. Every command is checked against the burner's limits and logged."
   - When checked (live, and rendered on load when saved as on) an inline `alert alert-warning` with `glyphicon-warning-sign` appears directly under the switch: "Anyone who can reach your Home Assistant or MQTT broker can change burner settings while this is on. Use a broker password and TLS."
   - No modal confirmation (defaulted: modals are heavy on phones; the inline warning plus the save message below carry the caution).
2. **Refresh interval** (`name="refresh"`, `type="number"`, `inputmode="numeric"`, `min=10`, `max=3600`, default 60): label "Refresh interval (seconds)". Help: "All values are re-published this often, even when unchanged. Changes are always published immediately." `col-xs-12 col-sm-4`.

### Action row
Below the panels, inside the form: `<button type="submit" class="btn btn-primary mqtt-save">Save settings</button>` then `<button type="submit" class="btn btn-default mqtt-test" formaction="${webroot}/homeassistant/test">Test connection</button>`, then `<p id="mqtt-test-result" role="status" aria-live="polite" class="mqtt-test-result"></p>` for the JS test result.
- Test connection is a real submit button with `formaction`, so it works without JS (server re-renders the page with the result in the same alert style, nothing is saved). With JS it is intercepted via `fetch` and the result appears in `#mqtt-test-result`.
- Save is `disabled` when web login credentials are not configured (same as Phase 8), with the hint "Saving is disabled until web login credentials are configured." Test connection is disabled for the same reason.

## Interaction Contract

**Access (D-10).** The page requires login exactly like the config editor: not signed in redirects to `${webroot}/auth/login` (existing behaviour). Save and Test are POSTs protected by the same same-origin/CSRF check as the config editor `save()`. Message text is always escaped (`${msg | h}`).

**Save (D-13).** Standard `<form method="post" action="${webroot}/homeassistant/save">`, works without JS. On submit: button text "Saving..." and disabled (no spinner library). Server validates all fields, stores them (password only if non-blank or cleared), and reconnects live. Response re-renders the page (POST/redirect/GET) with a message above the status line.

| Outcome | Style | Copy |
|---------|-------|------|
| Saved | `alert-success`, `role="status"` | Settings saved. Reconnecting to the broker... (status line then moves to Connected or Disconnected within a few seconds) |
| Saved while commands newly on | `alert-success` | Settings saved. Home Assistant can now change burner settings. |
| Saved while disabled | `alert-success` | Settings saved. Home Assistant publishing is off. |
| Validation failed | `alert-danger`, `role="alert"`, `tabindex="-1"`, focused on load | Could not save. Fix the highlighted fields and try again. |
| Not signed in / cross-origin | `alert-danger` | Could not save the settings. Sign in again and retry. |
| Daemon down | `alert-danger` | Cannot save right now because the PellMon server is not running. Your changes were not saved. Start the server and retry. |
| Auth not configured | help text, buttons disabled | Saving is disabled until web login credentials are configured. |

**Test connection (D-13).** Uses the current form values without saving them. If the password field is blank it uses the stored password (server side; the browser never sees it).

| State | Button | Message |
|-------|--------|---------|
| Idle | "Test connection" enabled | (empty) |
| Testing | "Testing..." disabled, `aria-busy="true"`; 10 second timeout | Testing the connection... |
| Success | back to "Test connection" | Connection successful. The broker accepted the host, port, credentials and TLS settings. Nothing was saved. (`text-success`, `glyphicon-ok`) |
| Failure | back to "Test connection" | Test failed: {reason}. Nothing was saved. (`text-danger`, `glyphicon-remove`, same reason set as the status line) |
| Invalid form | back to idle | Test failed: fix the highlighted fields first. |
| Not signed in / daemon down | back to idle | Same copy as the corresponding Save error, with "test" instead of "save" where the word appears. |

Test never publishes anything and never changes the live connection.

**Validation (server-side authoritative; the same rules run in the browser only as `required`/`min`/`max` hints, no custom JS blocking).** Errors render per field: `.form-group.has-error`, `aria-invalid="true"`, and a `<span class="help-block" id="{field}-error">` referenced from `aria-describedby`. Fields with errors keep the user's input except the password.

| Field | Rule | Error copy |
|-------|------|------------|
| Broker host | required when enabled; 1-253 chars; no spaces; no `://` | Enter the broker host name or IP address, without mqtt:// and without spaces. |
| Port | integer 1-65535 | Port must be a number from 1 to 65535. |
| Username | 0-128 chars, no control characters | Username cannot contain control characters or be longer than 128 characters. |
| Password | 0-256 chars | Password cannot be longer than 256 characters. |
| Topic prefix | 1-64 chars; no `#`, `+`, spaces or control characters; not starting or ending with `/` | Topic prefix cannot be empty, contain spaces, # or +, or start or end with /. |
| Discovery prefix | same rule as topic prefix | Discovery prefix cannot be empty, contain spaces, # or +, or start or end with /. |
| Device identifier | required when enabled; 1-64 chars of letters, digits, `-`, `_` | Enter the device identifier, using only letters, digits, - and _ (up to 64 characters). |
| Device name | required when enabled; 1-64 chars | Enter a device name of up to 64 characters. |
| Refresh interval | integer 10-3600 | Refresh interval must be between 10 and 3600 seconds. |

When the enable switch is off, host, device identifier and device name are not required (so the page can be saved empty).

**Empty / first-run state (defaulted).** On a fresh install all fields show defaults (port 1883, TLS off, Verify on, prefix `scotte`, discovery prefix `homeassistant`, refresh 60, commands off, enable off), host/device identifier/device name are empty, the status line shows Off, and no password is stored. The page is fully usable and needs no separate empty-state screen. The "plugin not active" and "daemon down" states above replace the status line but keep the form visible (Save then returns the daemon-down error).

**Live JS behaviours (all progressive enhancement, page fully works without them).** (a) Status refresh every 5 s. (b) TLS toggles the Verify checkbox `disabled` state, the verification-off warning and the port swap. (c) Allow commands toggles its warning. (d) Prefix help text mirrors the typed prefix. (e) Save/Test "Saving..." / "Testing..." states and the test `fetch`. No other scripts, no polling of secrets.

## Mobile Behaviour (Phase 10 contract)

At 390px (content width 360px), everything stacks in one column; at 768px fields use the `col-sm-*` widths above (two per row where specified); nothing depends on hover.

- All field wrappers are `col-xs-12` plus the `col-sm-*` widths above; no bare `col-md-*`/`col-sm-*` without a `col-xs-*` sibling.
- Phone rules inside `@media (max-width: 767px)` only: `.mqtt-form .form-control { height: 44px; font-size: 16px; }` (16px prevents iOS focus zoom); `.mqtt-form .checkbox label { min-height: 44px; padding: 8px 0 8px 32px; line-height: 28px; display: block; }` with the checkbox input positioned at `margin-left: -32px` and enlarged to 24x24px so the whole row is the target; `.mqtt-form .btn { display: block; width: 100%; min-height: 44px; margin: 0 0 8px; }`; panel headings 18px/600. (Panel body and alert padding are 16px on all breakpoints and are set globally, see Spacing exceptions, not only on phones.)
- Button order on phones: Save settings first (full width), Test connection below it (full width), test result under both. From 768px they sit inline (`display: inline-block; width: auto`), Save then Test, 8px apart.
- The status line and messages wrap; `.container { overflow-wrap: break-word; }` (Phase 10 shared rule) and `.mqtt-form code { word-break: break-all; }` prevent long prefixes or hosts pushing the page wider than 360px.
- Long host, username or device identifier values must not overflow: `.form-control` is `width: 100%` and inputs are never given fixed pixel widths.
- No horizontal scrolling on the page, no `overflow-x: hidden` on `body`.
- Adjacent tap targets are at least 8px apart (checkbox rows have 8px vertical gap, buttons 8px).

## Accessibility

- Every input has a visible `<label for="...">`; placeholders are never the only label (placeholder `set` on the password is supplemental, the label "Password" is always present).
- Help text linked by `aria-describedby` (`{field}-help`, plus `{field}-error` when invalid). Checkbox groups are inside `<fieldset>` with a `<legend class="sr-only">` matching the panel heading.
- Status line `role="status"` `aria-live="polite"`; validation summary `role="alert"` and focused; test result `role="status"`. `aria-busy="true"` on Test while running.
- Disabled Verify checkbox uses the native `disabled` attribute (not just styling) and its help text says why: shown only while TLS is off as "Turn on TLS to change this."
- State never depends on color alone (glyph plus words in every status and message).
- Focus outlines are never removed; keyboard order follows visual order: enable, host, port, username, password, (clear password), TLS, verify, prefix, discovery prefix, device id, device name, allow commands, refresh, Save, Test.
- Text contrast on `#fff` and on the Bootstrap alert backgrounds meets 4.5:1 (Bootstrap defaults are accepted).
- The password field is `type="password"` with `autocomplete="new-password"` so browsers do not autofill the login password into it.

## Defaulted Decisions (summary for planner)

1. Route `/homeassistant/` with `save`, `test`, `status` endpoints; navbar label "Home Assistant" after Settings; tablet-only navbar link padding of 8px (on the 4px grid, saves 98px) to keep seven links on one row at 768px.
2. One form and one Save for all five panels (single reconnect), not one form per panel.
3. No modal for enabling commands; inline warning plus save message instead.
4. Extra "Remove the stored password" checkbox (only shown when a password is stored), because a blank field must keep the current value.
5. Device name and identifier have no default and are placeholders only; nothing device-specific is hard-coded.
6. Status line polls every 5 s; Test has a 10 s timeout; times shown as server-local `HH:MM:SS`.
7. Port auto-swaps between 1883 and 8883 when TLS is toggled only if it still holds the other standard port.
8. Failure reasons come from a fixed mapped set, never raw exception text.
9. Test connection is a `formaction` submit button, so it works without JS.
10. Helper text is 14px (Phase 10), not 12px (Phase 8).
