<objective>
Give the daemon a validated, persistent key/value settings API over D-Bus, backed by the
existing `pellmon_settings.db` in the Phase 7 data folder.

Purpose: the web container mounts `/var/lib/pellmon` read-only (docker-compose.yml), so the
web process cannot persist the user's system-image choice itself. The daemon is the only
writer of that folder, and its settings DB is already backed up by `tools/pellmon_backup.py`
with no change needed. This plan is the storage half of D-05 and the daemon half of D-02's
two-tier whitelist.

Output: `Keyval_storage.getval()`, a daemon-side `ALLOWED_SETTINGS` whitelist,
`GetSetting`/`SetSetting` on `MyDBUSService`, and a real-sqlite test module.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| web process -> daemon (D-Bus `org.pellmon.int`) | The web process is internet-adjacent (CherryPy on 8081); anything it forwards over D-Bus is attacker-influenced input to the daemon. The session bus is private to the compose stack, but the daemon must not treat that as authentication. |
| daemon -> `pellmon_settings.db` | Writes land in the Phase 7 persistent host folder; the same table holds plugin `Storeditem` rows. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | `MyDBUSService.SetSetting` | mitigate | Key must be a member of `ALLOWED_SETTINGS`; without this an attacker reaching D-Bus could overwrite any plugin `Storeditem` row (e.g. a stored burner setpoint) in the shared `keyval` table. |
| T-08-02 | Tampering / Information disclosure | value of `web.system_image` | mitigate | Anchored `^system[a-z0-9_]*\.svg$` validator; no path separators, no `..`, no NUL, no absolute paths can be stored, so the value can never steer `serve_file` outside `media/img` (D-02). |
| T-08-03 | Denial of service | `GetSetting` on every main-page load | accept | Single indexed SELECT on a local sqlite file with an existing lock; `getval` returns a default instead of raising, so a corrupt/absent DB degrades to the config fallback rather than failing the page. |
| T-08-04 | Repudiation | silent rejection | mitigate | Every whitelist rejection logs `logger.warning` with the key (and value repr) via the shared `pellMon` logger, which is already forwarded to the web UI event stream by `dbus_signal_handler`. |
| T-08-05 | Information disclosure | settings DB file mode | mitigate | No change: `Keyval_storage.__init__` already pre-creates and chmods the file 0600 (Phase 7). This plan must not add any code path that creates the DB by another route. |
| T-08-SC | Tampering | package installs | accept | No package-manager installs in this phase (RESEARCH: "Package Legitimacy Audit: not applicable"); nothing is added to requirements.txt. |
</threat_model>
