<objective>
Wire the daemon setting and the dbus-free controller into the running web app, and build the
page the user actually sees.

Purpose: plans 08-01 and 08-02 produced storage and logic with no route and no HTML. This plan
mounts `/settings/`, adds the D-Bus proxy methods, makes `Root.systemimage` resolve the image
per request (so D-04's "no restart" holds and the browser cannot serve a stale SVG), and
implements the approved UI contract.

Output: the `/settings/` route, a per-request `systemimage` handler, `html/settings.html`, the
navbar entry, the gallery CSS, and render tests.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `Root.systemimage` | `**args` query parameters are attacker-controlled; the handler must ignore them entirely for path selection. |
| stored setting -> `serve_file` | The only place a stored string could become a filesystem path. |
| stored/flash values -> rendered HTML | Mako output is the XSS sink. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-13 | Information disclosure | `Root.systemimage` | mitigate | Path comes only from `effective_image(system_image_dir, dbus.get_setting, system_image)`; `**args` is never read for path selection, so `systemimage?rand=../../etc/passwd` cannot influence the served file. The function returns either the config global or a join of the fixed image dir with a `SYSTEM_IMAGES` member. |
| T-08-14 | Tampering (XSS) | `settings.html` | mitigate | Every dynamic interpolation uses the `| h` filter; a dedicated render test asserts a `<script>` payload in `msg` comes out escaped. Thumbnails use `<img>`, never `<object>` or inline SVG, so a tampered SVG cannot execute script in the page origin. |
| T-08-15 | Information disclosure | browser cache of `/systemimage` | mitigate | `Cache-Control: no-cache` plus `Pragma: no-cache`, because the existing `rand` cache-buster is fixed per process (RESEARCH A1) and a shared-browser install would otherwise keep showing the previous diagram. |
| T-08-16 | Denial of service | `systemimage` D-Bus call per request | accept | Already-wrapped single local call; on failure `effective_image` returns the config path, so the main page never errors. |
| T-08-17 | Elevation of privilege | `/settings/` route exposure | mitigate | Mounting is a plain attribute on `PellMonWeb`; the auth gate lives on the handlers themselves (`@require()` from plan 08-02), so mounting cannot accidentally create an unauthenticated write path. A test asserts both handlers still carry `auth.require` after wiring. |
| T-08-SC | Tampering | package installs | accept | No package-manager installs; no `requirements.txt` change. Bootstrap 3 and Glyphicons are already vendored at `media/bs3`. |
</threat_model>
