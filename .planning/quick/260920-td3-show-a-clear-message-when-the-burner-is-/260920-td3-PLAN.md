<objective>
Replace the Scotte plugin's silent dummy-data fallback with an explicit, live connection
state, and surface it as a friendly banner on the web main page.

Purpose: on a heating appliance, a UI that looks normal while serving fabricated values is
dangerous. The user's Pi has no burner attached yet and the UI gives no hint of that.
Output: a `burner_connection` / `burner_connection_reason` item pair in the daemon database,
a banner + greyed-out widgets on the main page, tests at protocol / plugin / web level, a WSL
end-to-end dry run, small doc edits, and a PR into master.

Scope guard: Scotte only. NBE is out of scope, but item names and the web code must not be
Scotte-specific, so the nbecom plugin can provide the same two items later.
</objective>

- `Database.run` (line ~118) loops every 2 s over all items, reads `item.get_text(item.value)`

  JSON through `MyDBUSService.changed_parameters`. Exceptions per item are swallowed. This is the
  only wiring needed for live updates: plain items whose `.value` changes propagate automatically.
- `MyDBUSService.GetItem(param)` returns `conf.database.get_text(param)`; an item whose getter
  raises propagates a D-Bus error to the web process.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| burner hardware -> serial read | untrusted/absent device bytes parsed by Frame.parse |
| daemon -> web (D-Bus) | item values, including the new reason string, cross into HTML |
| browser -> web | existing; unchanged by this plan |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-td3-01 | Spoofing | dummy fallback serving fake burner values as real | mitigate | open failure sets no_connection and serves nothing; the only fabricated-value path is demo mode, which is labelled in the UI |
| T-td3-02 | Information disclosure | connection_reason rendered into the main page | mitigate | reason is built from the configured port name and the OS error only, never credentials; render through mako's default escaping, never with the `| n` filter |
| T-td3-03 | Tampering | reason string as an XSS vector via a crafted config value | mitigate | escape on render; the reason line is text content, set via textContent in JS, never innerHTML |
| T-td3-04 | Denial of service | state-change callback raising inside the protocol poll thread | mitigate | callback invoked inside try/except; a broken consumer cannot stop polling |
| T-td3-SC | Tampering | npm/pip installs | accept | no new dependencies; no package installs in this plan |
